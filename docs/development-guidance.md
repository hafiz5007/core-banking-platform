## 1. Five-minute start

```bash
# 1. Prerequisites: JDK 21, Maven 3.9+, Docker Desktop running.
java -version && mvn -v && docker info

# 2. Configuration — every setting and secret lives in one gitignored .env
cp .env.example .env

# 3. Build the whole reactor without tests (fastest path to runnable jars)
mvn -B -DskipTests package

# 4. Full build with unit + integration tests (needs Docker for Testcontainers)
mvn -B verify

# 5. Run the platform
docker compose up --build          # see section 10 for the known ledger-grpc-api build gap
```

Then:

| What | URL |
|------|-----|
| API gateway (front door) | `http://localhost:8080/api/v1/...` |
| Swagger UI (any service) | `http://localhost:<port>/swagger-ui.html` |
| Health | `http://localhost:<port>/actuator/health` |
| Prometheus metrics | `http://localhost:<port>/actuator/prometheus` |
| Gateway routes | `http://localhost:8080/actuator/gateway/routes` |

## 2. Architecture

### 2.1 What this system is

A **Java 21 / Spring Boot 3.4 microservice platform** for retail core banking with domestic and
cross-border payments. Thirteen Maven modules under one parent reactor (`banking-platform-parent`,
`com.bank:0.1.0-SNAPSHOT`): two shared libraries, ten business services, one gateway.

The style is **hexagonal (ports and adapters)** in every service, **synchronous HTTP/gRPC** between
services, **one PostgreSQL instance with a private schema per service**, and **config-switched
adapters** so every external integration has a working stub for local development and tests.

### 2.2 Module map

| Module | Type | Port | DB schema | Owns |
|--------|------|------|-----------|------|
| `common-lib` | library | – | – | `Money`, error model, correlation-id filter, tenant context, service-auth (JWT) issuer/verifier + HTTP and gRPC interceptors |
| `ledger-grpc-api` | contract | – | – | `ledger_posting.proto` — the gRPC contract, generated by `protobuf-maven-plugin` |
| `api-gateway` | service | 8080 | stateless | Spring Cloud Gateway MVC: path routing, OAuth2 resource server, per-client rate limiting |
| `account-service` | service | 8081 | `account` | Accounts, product catalogue, holders/mandates, change log, ledger provisioning + gRPC debit posting |
| `customer-service` | service | 8082 | `customer` | Onboarding, KYC, sanctions/PEP screening, risk rating, consent, Open Banking TPP consents |
| `ledger-service` | service | 8083 (+**9090 gRPC**) | `ledger` | Double-entry GL: chart of accounts, balanced postings, idempotent replay, reversal, trial balance |
| `payment-service` | service | 8084 | `payment` | Payment engine + rail strategies (intrabank / instant / RTGS / ACH / cross-border), saga + compensation, outbox, standing orders, direct debits, P2P aliases, bill pay |
| `interest-fee-service` | service | 8085 | `interest` | Interest accrual and capitalization, fees, end-of-day batch |
| `card-service` | service | 8086 | `card` | Card issuance (tokenized PAN), authorization + holds, usage controls, settlement, clearing reconciliation |
| `notification-service` | service | 8087 | `notification` | Alerts, OTP (hashed, single-use, rate-limited), statement dispatch |
| `risk-aml-service` | service | 8088 | `risk` | Real-time transaction monitoring, alerts, AML cases, SAR filing |
| `admin-service` | service | 8089 | `admin` | RBAC, maker-checker (four-eyes), immutable audit trail |
| `reporting-service` | service | 8090 | `reporting` | Operational and regulatory reports from a metrics projection |

### 2.4 Inside a service — hexagonal layout

Every service follows the same package shape (`account-service` is the reference):

```
src/main/java/com/bank/<service>/
├── domain/                    # aggregates, value objects, enums — NO framework imports
├── application/               # use-cases / orchestration
│   └── port/                  # outbound interfaces the domain needs (LedgerPort, ScreeningPort…)
├── adapter/
│   ├── in/web/                # REST controllers + DTOs + GlobalExceptionHandler
│   ├── in/scheduler/          # cron-driven entry points (EOD, standing orders)
│   ├── out/persistence/       # Spring Data JPA repositories
│   └── out/<integration>/     # HTTP / gRPC / stub adapters implementing the ports
├── config/                    # OpenAPI, gRPC client, security wiring
└── <Service>Application.java

src/main/resources/
├── application.yml
└── db/migration/V<n>__<name>.sql    # Flyway, forward-only
```

**The rule that matters:** the direction of dependency is always inward. `domain` imports nothing
from Spring or JPA; `application` depends on `domain` and on its own `port` interfaces;
`adapter` depends on `application`. Never the reverse.

### 2.5 Cross-cutting concerns (all in `common-lib`)

| Concern | Class | Behaviour |
|---------|-------|-----------|
| Money | `com.bank.common.money.Money` | `BigDecimal` + ISO-4217. Cross-currency arithmetic throws `CurrencyMismatchException`. **Never use `double`/`float` for money.** |
| Errors | `ApiError`, `ErrorCode`, `BusinessException`, `ResourceNotFoundException` | RFC 9457 problem+json. Each service maps them in its `GlobalExceptionHandler`. |
| Correlation | `CorrelationIdFilter` | Reads/creates `X-Correlation-Id`, puts it in SLF4J MDC; every log line carries `correlationId=…`. Propagated outbound. |
| Multi-tenancy | `TenantContext`, `TenantContextFilter` | Request-scoped organization from `X-Organization-Id`, falling back to `DEFAULT` (ADR-002). |
| Service auth | `ServiceTokenIssuer`, `ServiceTokenVerifier`, `ServiceTokenAuthFilter`, `JwtClientInterceptor`, `JwtServerInterceptor` | Short-lived HMAC JWTs on east-west calls, over both REST and gRPC (ADR-008). Auto-configured via `ServiceAuthAutoConfiguration`. |

`common-lib` is a **plain library** — Spring Boot repackaging is disabled, and `grpc-api`,
`spring-web`, `spring-boot-autoconfigure` and `jakarta.servlet-api` are `provided` so consumers
bring their own runtime.

### 2.6 Data

- **One PostgreSQL 16 instance**, database `banking`, **one schema per service**. Migrations never
  collide and each service owns its tables.
- **Flyway** on startup: `classpath:db/migration`, `create-schemas: true`, forward-only.
- **Hibernate `ddl-auto: validate`** — the schema must match the entities exactly, or the service
  refuses to start. This is deliberate: it catches migration/entity drift at boot, not in production.
- `open-in-view: false` everywhere — lazy collections must be fetch-joined in the repository, not
  touched in the controller.
- UTC everywhere (`hibernate.jdbc.time_zone: UTC`).

### 2.7 Integration patterns

| Pattern | Where | Notes |
|---------|-------|-------|
| **Ports + swappable adapters** | every outbound integration | Chosen by config, never by code change. e.g. `ledger.provisioning=off\|http`, `ledger.posting=off\|grpc`, `screening.adapter=stub\|risk-service`. |
| **gRPC** | account-service → ledger-service `:9090` | ADR-007. Contract in `ledger-grpc-api`; hot-path posting. Server is off by default (`grpc.server.enabled`), compose turns it on. |
| **Transactional outbox** | payment-service `OutboxRelay` | `@Scheduled(fixedDelayString = "${outbox.relay.delay-ms:5000}")`. ADR-004. |
| **Saga + compensation** | payment-service | Rail failure reverses the ledger posting; the payment ends `COMPENSATED`, never silently lost. |
| **Idempotency** | ledger entries, payment initiation | `idempotencyKey` — a replay returns the original result, no double-post. |
| **Scheduled batches** | interest-fee `EodScheduler` (`0 0 23 * * *`), payment `StandingOrderScheduler` (`0 30 0 * * *`) | **Both off by default** (`CBP_EOD_SCHEDULER_ENABLED`, `CBP_STANDING_ORDERS_SCHEDULER_ENABLED`) so a local or CI run never fires one; each has an API endpoint that runs the same work on demand. |
| **Resilience** | all outbound HTTP | Timeouts + correlation-id propagation. A failed screening call **rejects** the payment; it is never fail-open. Ledger provisioning treats HTTP 409 as idempotent success. |

### 2.8 Security model

**Edge (north-south)** — `api-gateway` is an OAuth2 resource server. With
`gateway.security.enabled=true`, every `/api/v1/**` request needs a valid bearer JWT from the bank
IdP (`spring.security.oauth2.resourceserver.jwt.issuer-uri`). Actuator stays open for probes. Rate
limiting runs before routing. **Default is `false`** so the platform boots without an IdP.

**East-west** — two layers:

1. **Network** — only the gateway is exposed. In Kubernetes: NetworkPolicies + mTLS via mesh.
2. **Service tokens (ADR-008)** — short-lived HMAC JWTs. Off by default. `service-auth.enabled`
   makes a service *mint* tokens for outbound calls; `service-auth.require-inbound` makes it
   *refuse* unauthenticated inbound calls. Receivers (`ledger-service`, `risk-aml-service`) default
   `require-inbound: true`; callers default `false`.

   ```bash
   echo "CBP_SERVICE_AUTH_SECRET=$(openssl rand -base64 48)" >> .env   # must be >= 32 bytes
   echo "CBP_SERVICE_AUTH_ENABLED=true" >> .env
   ```

   **Roll out callers before receivers** when enabling across environments.

**Always** — TLS 1.2+ externally, secrets from Vault/KMS at runtime, no PII/PAN/secrets in logs,
privileged actions written to the immutable audit trail in `admin-service`.

## 4. Build commands

All commands run from the **repository root** unless stated otherwise.

### 4.1 Everyday builds

```bash
# Fast: compile + package every module, skip all tests. Produces runnable Spring Boot jars.
mvn -B -DskipTests package

# Full: compile + unit tests + integration tests. Requires Docker. This is what CI runs.
mvn -B verify

# Clean rebuild and install artifacts into the local ~/.m2 repository.
# Do this after changing common-lib or ledger-grpc-api so other modules see the new version.
mvn -B clean install -DskipTests

# Compile only, no packaging (quickest feedback on a syntax/type error)
mvn -B -q compile
```

### 4.2 Building one module (and what it depends on)

```bash
# -pl = project list, -am = also make required upstream modules (common-lib, ledger-grpc-api)
mvn -B -pl account-service -am -DskipTests install

# Just this module, assuming its dependencies are already installed
mvn -B -pl payment-service install

# Resume a failed reactor build from a given module instead of starting over
mvn -B install -rf :risk-aml-service

# Keep going after a module fails, so you see every failure in one run
mvn -B clean install -fae
```

### 4.3 Regenerating the gRPC stubs

`ledger-grpc-api` generates Java from `src/main/proto/ledger_posting.proto` at build time.
After editing the `.proto`:

```bash
mvn -B -pl ledger-grpc-api clean install
mvn -B -pl account-service,ledger-service -am -DskipTests install
```

Generated sources land in `ledger-grpc-api/target/generated-sources/protobuf/`. If your IDE
shows "cannot resolve symbol" on generated classes, re-import the Maven project.

### 4.4 Quality gate

```bash
# Formatting (Spotless / google-java-format) + JaCoCo coverage floor (40% instructions per module)
mvn -B verify -Pquality

# Coverage only — Spotless currently rejects 10 pre-existing files (see section 12)
mvn -B verify -Pquality -Dspotless.check.skip=true

# Apply the formatter across the repo (mechanical, touches nearly every file — discuss first)
mvn -Pquality spotless:apply
```

Coverage reports: `<module>/target/site/jacoco/index.html`.

### 4.5 Useful build flags

| Flag | Effect |
|------|--------|
| `-B` | Batch mode — no ANSI, cleaner logs. Always use in CI and when piping output. |
| `-o` | Offline. Fast when dependencies are already cached. |
| `-q` | Quiet — warnings and errors only. |
| `-T 1C` | Parallel build, one thread per core. Safe for `-DskipTests`; avoid with Testcontainers ITs. |
| `-Ddocker.api.version=1.41` | Docker Engine API version Testcontainers negotiates. Default `1.41`; override if your daemon needs another. |
| `-DskipITs` | Skip failsafe integration tests, still run unit tests. |
| `-DskipTests` | Skip both surefire and failsafe. |

## 5. Run commands

### 5.1 Everything, in Docker (the normal path)

```bash
cp .env.example .env          # once — .env is gitignored, never commit it
docker compose up --build     # build images and start Postgres + all 11 services

docker compose up -d          # detached
docker compose ps             # what is running, and health
docker compose logs -f payment-service
docker compose down           # stop, keep the pgdata volume
docker compose down -v        # stop AND wipe the database (fresh Flyway run next boot)
docker compose up -d --build ledger-service   # rebuild and restart one service
```

Compose wires the "fully integrated" profile automatically: `CBP_LEDGER_PROVISIONING=http`,
`CBP_LEDGER_POSTING=grpc`, `CBP_SCREENING_ADAPTER=risk-service`, gateway routing to every service.

> See section 10.1 — the per-service Dockerfiles do not currently copy `ledger-grpc-api`, so
> `docker compose build` fails until that one-line fix is applied.

### 5.2 One service, on the host

Start only the database in Docker, run the service from Maven:

```bash
docker compose up -d postgres

# Install shared modules once
mvn -B -DskipTests install -pl common-lib,ledger-grpc-api

# Then run a service (defaults: localhost:5432/banking, banking/banking)
mvn -B -pl account-service spring-boot:run
```

Override any property on the command line:

```bash
mvn -pl account-service spring-boot:run \
  -Dspring-boot.run.arguments="--server.port=9081 --ledger.provisioning=http --ledger.posting=off"
```

Or run the packaged jar directly:

```bash
mvn -B -DskipTests package
java -jar account-service/target/account-service-0.1.0-SNAPSHOT.jar --server.port=8081
```

### 5.3 Mixed mode (most common while developing)

Run the platform in compose, stop the one service you are working on, run that one from your IDE
against the same database and neighbours:

```bash
docker compose up -d
docker compose stop payment-service
CBP_SERVER_PORT=8084 CBP_LEDGER_BASE_URL=http://localhost:8083 CBP_RISK_BASE_URL=http://localhost:8088 \
  CBP_SCREENING_ADAPTER=risk-service \
  mvn -pl payment-service spring-boot:run
```

### 5.4 Configuration reference

Everything is environment-driven with a safe default in `application.yml`. **An unset variable
turns a feature off rather than enabling it weakly.**

> **Every variable is prefixed `CBP_`** so this project's settings cannot collide with another
> project's on the same machine. The prefix is part of the name the services read — an unprefixed
> `DB_URL` or `SERVER_PORT` is ignored.

| Variable | Default | Meaning |
|----------|---------|---------|
| `CBP_DB_URL` / `CBP_DB_USER` / `CBP_DB_PASSWORD` | `jdbc:postgresql://localhost:5432/banking`, `banking`, `banking` | Datasource for every service |
| `CBP_POSTGRES_DB` / `_USER` / `_PASSWORD` | `banking` / `banking` / `banking` | Read by `docker-compose.yml` to create the database container |
| `CBP_SERVER_PORT` | per service (8080–8090) | HTTP port |
| `CBP_LEDGER_BASE_URL` | `http://localhost:8083` | Ledger REST endpoint used by payment/card/interest/account |
| `CBP_LEDGER_PROVISIONING` | `off` | `off` \| `http` — create a GL account when a bank account opens |
| `CBP_LEDGER_POSTING` | `off` | `off` \| `grpc` — post account debits over gRPC (ADR-007) |
| `CBP_LEDGER_GRPC_TARGET` | `localhost:9090` | gRPC address of ledger-service |
| `CBP_LEDGER_SETTLEMENT_ACCOUNT` | `SETTLEMENT` | GL account credited on a customer debit |
| `CBP_GRPC_SERVER_ENABLED` / `CBP_GRPC_PORT` | `false` / `9090` | ledger-service gRPC listener |
| `CBP_SCREENING_ADAPTER` | `stub` | `stub` \| `risk-service` — payment screening adapter |
| `CBP_RISK_BASE_URL` | `http://localhost:8088` | risk-aml-service endpoint |
| `CBP_CLEARING_SETTLEMENT_ACCOUNT` / `CBP_CROSSBORDER_NOSTRO_ACCOUNT` | `SETTLEMENT` / `NOSTRO` | Payment rail GL accounts |
| `CBP_INTEREST_EXPENSE_ACCOUNT` / `CBP_FEE_INCOME_ACCOUNT` | `INTEREST-EXPENSE` / `FEE-INCOME` | interest-fee-service GL accounts |
| `CBP_CARD_SETTLEMENT_ACCOUNT` | `CARD-SETTLEMENT` | card-service settlement GL account |
| `CBP_AML_LARGE_AMOUNT_THRESHOLD` | `10000` | Amount at/above which risk-aml holds a transaction |
| `CBP_SERVICE_AUTH_ENABLED` | `false` | Mint service JWTs on outbound calls |
| `CBP_SERVICE_AUTH_REQUIRE_INBOUND` | `true` on ledger/risk, `false` elsewhere | Refuse unauthenticated inbound calls |
| `CBP_SERVICE_AUTH_SECRET` | *(empty)* | HMAC secret, **>= 32 bytes**, refused at startup if shorter |
| `CBP_SERVICE_AUTH_ISSUER` / `_TOKEN_TTL` / `_CLOCK_SKEW` | `core-banking-platform` / `60` / `30` | Token issuer, lifetime, allowed clock drift (seconds) |
| `CBP_GATEWAY_SECURITY_ENABLED` | `false` | Enforce OAuth2 JWT at the edge |
| `CBP_GATEWAY_JWT_ISSUER_URI` | *(empty)* | Bank IdP issuer — bound to `spring.security.oauth2.resourceserver.jwt.issuer-uri` |
| `CBP_GATEWAY_RATE_LIMIT` | `120` | Requests per minute per client at the gateway |
| `CBP_<SERVICE>_URI` (`CBP_ACCOUNT_URI`, `CBP_PAYMENT_URI`, …) | `http://localhost:<port>` | Gateway route targets |
| `CBP_EOD_SCHEDULER_ENABLED` / `CBP_EOD_SCHEDULER_CRON` | `false` / `0 0 23 * * *` | End-of-day accrual batch. Off by default; the API runs the same work on demand. |
| `CBP_STANDING_ORDERS_SCHEDULER_ENABLED` / `CBP_STANDING_ORDERS_SCHEDULER_CRON` | `false` / `0 30 0 * * *` | Standing-order execution batch. Off by default. |
| `CBP_OUTBOX_RELAY_DELAY_MS` | `5000` | How often the outbox relay polls for unpublished events, in milliseconds. |

## 6. Debug commands

### 6.1 Remote JVM debugging (attach your IDE on port 5005)

**Service started by Maven:**

```bash
mvn -pl payment-service spring-boot:run \
  -Dspring-boot.run.jvmArguments="-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005"
```

**Packaged jar:**

```bash
java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005 \
     -jar payment-service/target/payment-service-0.1.0-SNAPSHOT.jar
```

**A service running in compose** — add to that service in `docker-compose.yml`:

```yaml
    environment:
      JAVA_TOOL_OPTIONS: "-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005"
    ports:
      - "5005:5005"
```

Then in your IDE: *Remote JVM Debug → localhost:5005*. Use `suspend=y` when you need to catch
something during startup (Flyway, bean wiring) — the JVM waits for you to attach.

**A Maven test run:**

```bash
mvn -pl ledger-service -Dmaven.surefire.debug test          # unit tests, listens on 5005
mvn -pl ledger-service -Dmaven.failsafe.debug verify        # integration tests, listens on 5005
```

### 6.2 Turning up the logs

```bash
# One package, at runtime, without a rebuild
mvn -pl payment-service spring-boot:run \
  -Dspring-boot.run.arguments="--logging.level.com.bank.payment=DEBUG --logging.level.org.springframework.web=DEBUG"

# See every SQL statement and its bound parameters
  ... "--spring.jpa.show-sql=true --logging.level.org.hibernate.orm.jdbc.bind=TRACE"

# Flyway migration detail
  ... "--logging.level.org.flywaydb=DEBUG"

# In compose
docker compose logs -f --tail=200 payment-service
docker compose logs -f | grep 'correlationId=abc-123'      # follow one request across services
```

Every log line carries `[<service>,correlationId=<id>]`. Send `X-Correlation-Id: <your-id>` on a
request and you can grep the whole distributed flow with it.

### 6.3 Runtime introspection

```bash
curl -s localhost:8084/actuator/health | jq            # liveness/readiness detail
curl -s localhost:8084/actuator/info
curl -s localhost:8084/actuator/metrics | jq
curl -s localhost:8084/actuator/metrics/http.server.requests | jq
curl -s localhost:8084/actuator/prometheus | head -40
curl -s localhost:8080/actuator/gateway/routes | jq    # gateway: what routes where
open http://localhost:8084/swagger-ui.html            # live API docs
curl -s localhost:8084/v3/api-docs | jq               # raw OpenAPI 3 spec
```

Exposed actuator endpoints are limited on purpose: the ten business services expose
`health,info,prometheus,metrics`; the **gateway** exposes `health,info,prometheus,gateway`
instead — it has no `/actuator/metrics`. Add more only in a local profile, never in a shared
environment.

### 6.4 Database

```bash
# Shell into Postgres
docker compose exec postgres psql -U banking -d banking

# Inside psql
\dn                                   -- list schemas (account, ledger, payment, …)
\dt payment.*                         -- tables in a schema
select * from payment.flyway_schema_history order by installed_rank desc limit 10;
select * from ledger.journal_entry order by created_at desc limit 5;

# One-liner from the host
docker compose exec -T postgres psql -U banking -d banking \
  -c "select version, description, success from ledger.flyway_schema_history order by installed_rank;"
```

Each service has its **own** `flyway_schema_history` inside its own schema.

### 6.5 gRPC

```bash
# ledger-service publishes the posting service on 9090 when CBP_GRPC_SERVER_ENABLED=true
docker compose exec ledger-service sh -c 'echo grpc listening on 9090'
grpcurl -plaintext localhost:9090 list                 # if you have grpcurl installed
```

`FakeLedgerPostingServer` in `account-service/src/test/.../adapter/out/ledger/` is an in-process
gRPC server used by `DebitAccountGrpcIT` — read it to see the expected wire behaviour.

### 6.6 Container-level debugging

```bash
docker compose ps                          # health and exit codes
docker compose logs ledger-service | tail -100

docker inspect $(docker compose ps -q payment-service) | jq '.[0].State'
```

## 7. Test commands

### 7.1 The test pyramid in this repo

### 7.3 Testcontainers — how integration tests work here

Each service has an `AbstractIntegrationTest` that all its `*IT` classes extend:

```java
@SpringBootTest(webEnvironment = RANDOM_PORT)
public abstract class AbstractIntegrationTest {
    @ServiceConnection
    static final PostgreSQLContainer<?> POSTGRES = new PostgreSQLContainer<>("postgres:16-alpine");
    static { POSTGRES.start(); }   // singleton — started once per JVM, never stopped
}
```

Two deliberate details, both of which were bugs once (see `docs/PENDING_TASKS.md` §0):

1. **The container is a singleton in a static block, not `@Container`.** Spring caches the
   application context *across* test classes; a per-class container gets torn down while a later
   class still points its `DataSource` at it. Ryuk reaps it at JVM exit.
2. **`docker.api.version` is a JVM system property, not an env var.** Docker Engine 29 dropped
   API < 1.40 and docker-java negotiates older by default, producing an opaque HTTP 400. The parent
   POM passes `-Dapi.version=1.41` to surefire and failsafe.

Speeding up local IT runs (optional):

```bash
# Reuse containers between runs — add testcontainers.reuse.enable=true to ~/.testcontainers.properties
echo "testcontainers.reuse.enable=true" >> ~/.testcontainers.properties

# Pre-pull the image so the first test does not wait on a download
docker pull postgres:16-alpine
```

## 8. Publish and release

### 8.1 What "publish" means here today

| Artifact | How it is produced | Where it goes today |
|----------|--------------------|---------------------|
| Spring Boot fat jars | `mvn package` | `<module>/target/<module>-0.1.0-SNAPSHOT.jar` — local only |
| Docker images | `docker compose build` / `docker build` | Local Docker daemon — **no registry configured** |
| Maven artifacts | `mvn install` | Local `~/.m2` — **no `distributionManagement`, so `mvn deploy` is not wired** |

Publishing to a registry is an open task. Sections 8.4–8.5 give the commands to add it.

### 8.2 Building release jars

```bash
mvn -B clean package -DskipTests                 # every module
mvn -B clean verify                              # every module, tested — do this for a real release
ls -la */target/*-0.1.0-SNAPSHOT.jar
```

`common-lib` and `ledger-grpc-api` produce **plain** jars (Boot repackaging is disabled); the other
eleven modules produce **executable** Boot jars.

### 8.3 Building Docker images

Every Dockerfile is a **multi-stage build** (`maven:3.9-eclipse-temurin-21` → `eclipse-temurin:21-jre`)
and expects the **repository root as the build context**:

```bash
# All service images, via compose
docker compose build
docker compose build --no-cache ledger-service

# One image, by hand — note the trailing "." (context = repo root) and -f pointing into the module
docker build -f account-service/Dockerfile -t core-banking/account-service:0.1.0 .

# Tag for a registry and push
docker tag core-banking/account-service:0.1.0 ghcr.io/<owner>/account-service:0.1.0
docker login ghcr.io
docker push ghcr.io/<owner>/account-service:0.1.0
```

Scripted, for all eleven runnable services:

```bash
VERSION=0.1.0
REGISTRY=ghcr.io/<owner>
for s in api-gateway account-service customer-service ledger-service payment-service \
         interest-fee-service card-service notification-service risk-aml-service \
         admin-service reporting-service; do
  docker build -f "$s/Dockerfile" -t "$REGISTRY/$s:$VERSION" . || exit 1
  docker push "$REGISTRY/$s:$VERSION"
done
```

### 8.4 Cutting a version

```bash
# Set the release version across the whole reactor
mvn -B versions:set -DnewVersion=0.2.0 -DprocessAllModules
mvn -B clean verify
git commit -am "release 0.2.0" && git tag -a v0.2.0 -m "0.2.0" && git push --follow-tags

# Move to the next snapshot
mvn -B versions:set -DnewVersion=0.3.0-SNAPSHOT -DprocessAllModules
mvn -B versions:commit          # or versions:revert to undo
```

`git describe --tags` should identify any build you ship. Consider stamping the version and git SHA
into `/actuator/info` via `spring-boot-maven-plugin` `build-info`.

### 8.5 To wire real publishing (not done yet)

- **Maven artifacts** — add `<distributionManagement>` (GitHub Packages, Nexus or Artifactory) to the
  parent POM plus a `settings.xml` server entry, then `mvn -B deploy -DskipTests`. Only `common-lib`
  and `ledger-grpc-api` are worth publishing — they are the shared contracts.
- **Container images** — add a `release.yml` GitHub Actions workflow triggered on `v*` tags, using
  `docker/login-action` + `docker/build-push-action` per service, tagged with the git tag and SHA.
- **Provenance** — sign images (cosign) and attach an SBOM (`syft`/`docker sbom`) before any
  environment beyond local. Required by the go-live gate.

## 9. End-to-end smoke test

Run this after `docker compose up` to prove the whole platform is wired. It exercises
customer → account → ledger → payment, including the ledger posting and the compensation path.

```bash
# 0. Everything healthy?
for p in 8080 8081 8082 8083 8084 8085 8086 8087 8088 8089 8090; do
  printf "%s -> " "$p"; curl -s "localhost:$p/actuator/health" | head -c 60; echo
done

# 1. Onboard a customer (customer-service)
curl -s -X POST localhost:8082/api/v1/customers -H 'Content-Type: application/json' -d '{
  "firstName":"Ada","lastName":"Lovelace","dateOfBirth":"1990-01-01","nationality":"GB",
  "email":"ada@example.com","taxId":"TAX123","dataProcessingConsent":true,"channel":"WEB"}'
# Surname "Sanctioned" -> BLOCKED (stub screening); "Refer"/"Fail" -> KYC REFERRED/FAILED, so the
# customer stays PENDING (stub KYC).

# 2. Create the two GL accounts the payments need (ledger-service)
curl -s -X POST localhost:8083/api/v1/ledger/accounts -H 'Content-Type: application/json' \
  -d '{"code":"1000","name":"Cash","accountType":"ASSET","currencyCode":"USD"}'
curl -s -X POST localhost:8083/api/v1/ledger/accounts -H 'Content-Type: application/json' \
  -d '{"code":"2000","name":"Customer Deposits","accountType":"LIABILITY","currencyCode":"USD"}'

# 3. Post a balanced double-entry and prove the books balance
curl -s -X POST localhost:8083/api/v1/ledger/entries -H 'Content-Type: application/json' -d '{
  "idempotencyKey":"dep-0001","narrative":"Customer deposit","lines":[
    {"accountCode":"1000","direction":"DEBIT","amount":"100.00"},
    {"accountCode":"2000","direction":"CREDIT","amount":"100.00"}]}'
curl -s localhost:8083/api/v1/ledger/trial-balance

# 4. Open a bank account (account-service; with CBP_LEDGER_PROVISIONING=http this also creates a GL account)
curl -s -X POST localhost:8081/api/v1/accounts -H 'Content-Type: application/json' \
  -d '{"customerId":"11111111-1111-1111-1111-111111111111","accountType":"SAVINGS","currencyCode":"USD"}'

# 5. Intrabank payment — validates, screens via risk-aml, posts to the ledger, confirms
curl -s -X POST localhost:8084/api/v1/payments -H 'Content-Type: application/json' -d '{
  "idempotencyKey":"pmt-0001","type":"INTRABANK","debtorAccount":"1000",
  "creditorAccount":"2000","amount":"25.00","currencyCode":"USD","narrative":"Rent"}'
# Re-run with the same idempotencyKey -> same payment, no double post.
# creditorAccount containing "BLOCKED" -> held by screening (422) — only with screening.adapter=stub.
# Under compose (risk-service) a hold instead needs amount >= CBP_AML_LARGE_AMOUNT_THRESHOLD (10000),
# or a high-risk counterparty country (XA/XB/XC).

# 6. Domestic clearing (ISO 20022 pacs.008)
curl -s -X POST localhost:8084/api/v1/payments -H 'Content-Type: application/json' -d '{
  "idempotencyKey":"rtgs-0001","type":"RTGS","debtorAccount":"1000",
  "creditorAccount":"GB29NWBK60161331926819","amount":"500.00","currencyCode":"USD","narrative":"Supplier"}'
# creditorAccount containing "RETURN" -> scheme rejects -> payment COMPENSATED (posting reversed).

# 7. Cross-border with FX + nostro settlement
curl -s -X POST localhost:8084/api/v1/payments -H 'Content-Type: application/json' -d '{
  "idempotencyKey":"xb-0001","type":"CROSS_BORDER","debtorAccount":"1000",
  "creditorAccount":"DE89370400440532013000","amount":"1000.00","currencyCode":"USD",
  "targetCurrencyCode":"EUR","narrative":"Overseas supplier"}'
# Response carries fxRate, targetAmount, targetCurrencyCode.

# 8. Same call, through the gateway instead of the service port
curl -s -H 'X-Correlation-Id: smoke-001' localhost:8080/api/v1/ledger/trial-balance
docker compose logs | grep smoke-001      # the request traced across services
```

**Deterministic test hooks** built into the stubs — useful in demos and tests:

| Input | Effect |
|-------|--------|
| Customer surname `Sanctioned` | Sanctions match → onboarding `BLOCKED` (`StubScreeningAdapter`) |
| Customer surname `Refer` | KYC `REFERRED` → onboarding stays `PENDING` (`StubKycVerificationAdapter`) |
| Customer surname `Fail` | KYC `FAILED` → onboarding stays `PENDING` (`StubKycVerificationAdapter`) |
| `creditorAccount` containing `BLOCKED` | Payment held by screening (HTTP 422). Needs `screening.adapter=stub` (the default on the host); compose uses `risk-service`, where a hold needs amount >= `CBP_AML_LARGE_AMOUNT_THRESHOLD` (10000) or country `XA`/`XB`/`XC` |
| `creditorAccount` containing `RETURN` | Rail rejects → saga compensates, payment `COMPENSATED` |

## 10. Troubleshooting

### 10.1 `docker compose build` fails: "Child module … does not exist"

**Known issue.** Each `Dockerfile` copies only `pom.xml`, `common-lib` and its own module — but the
parent POM declares all thirteen modules, and `account-service` / `ledger-service` also depend on
`ledger-grpc-api`. Maven inside the build stage cannot resolve the reactor.

**Fix** — copy the contract module into the build stage of every Dockerfile:

```dockerfile
COPY pom.xml .
COPY common-lib common-lib
COPY ledger-grpc-api ledger-grpc-api        # <-- add this line
COPY account-service account-service
RUN mvn -q -pl account-service -am -DskipTests package
```

`-am` then builds `common-lib` and `ledger-grpc-api` from source. If Maven still complains about
the other missing modules, either add `-N` handling or split the reactor POM; the simplest robust
alternative is to `COPY . .` and rely on a `.dockerignore` that excludes `target/`, `.git/` and `.env`.

### 10.2 Testcontainers cannot reach Docker (opaque HTTP 400)

Docker Engine 29 requires API ≥ 1.40; docker-java negotiates older by default.

```bash
mvn -B verify -Ddocker.api.version=1.41       # already the default; override if your daemon differs
```

`api.version` is a **JVM system property** — there is no env-var equivalent. It is passed by the
parent POM through surefire/failsafe `systemPropertyVariables`.

### 10.3 Windows / Docker Desktop: Testcontainers cannot find the daemon

```bash
DOCKER_HOST='npipe:////./pipe/dockerDesktopLinuxEngine' mvn -B verify
# or
DOCKER_API_VERSION=1.44 mvn -B install -pl account-service
```

Make sure Docker Desktop is running with the WSL2 backend and that "Expose daemon" is not required
by your setup. `docker info` must succeed in the same shell you run Maven from.

### 10.4 Service refuses to start: schema validation failure

`ddl-auto: validate` compares entities to the migrated schema. A mismatch (`wrong column type`,
`missing column`) means an entity changed without a matching Flyway migration.

```bash
docker compose down -v && docker compose up      # rebuild the database from scratch
```

Common cause seen in this repo: migrations declaring `CHAR(n)` while entities map `String`
(`varchar`). Always use `VARCHAR(n)`.

### 10.5 Flyway: "Migration checksum mismatch"

An already-applied migration file was edited. **Never edit an applied migration.** Either:

- drop the volume and re-migrate (`docker compose down -v`) — fine locally; or
- revert the edit and put the change in a **new** `V<n+1>__….sql`.

There is an open decision on exactly this, from the `CHAR`→`VARCHAR` fix — see
`docs/PENDING_TASKS.md` §0.

### 10.6 `mvn verify -Pquality` fails at Spotless

Pre-existing: google-java-format rejects 10 files whose style is the repo's house style (4-space
continuation indents, aligned `@param` javadoc, one record component per line).

```bash
mvn -B verify -Pquality -Dspotless.check.skip=true    # unblock yourself
mvn -Pquality spotless:apply                          # or adopt the formatter repo-wide
```

The decision (adopt google-java-format vs. switch to `palantirJavaFormat` / an Eclipse config) is
still open.

### 10.7 Integration tests compile but never run

Failsafe must be declared in `<build><plugins>`, not only in `<pluginManagement>`. It is correctly
declared in the parent POM today — if you create a new module, do not override that.

### 10.8 Port already in use

```bash
# Linux / macOS
lsof -i :8084 && kill -9 <pid>
# Windows
netstat -ano | findstr :8084
taskkill /PID <pid> /F
# Or just move the service
CBP_SERVER_PORT=9084 mvn -pl payment-service spring-boot:run
```

### 10.9 A service cannot reach another service

- In compose, use **service names**: `http://ledger-service:8083`, not `localhost`.
- On the host, use `localhost:<port>`.
- Check `docker compose ps` for health; `depends_on` waits for Postgres health but only for
  *started* on peer services — a peer may still be booting.

### 10.10 401/403 on internal calls after enabling service auth

`CBP_SERVICE_AUTH_SECRET` must be identical everywhere and **at least 32 bytes**. Enable
`CBP_SERVICE_AUTH_ENABLED=true` on **callers first**, then receivers. To troubleshoot a single
receiver, set `CBP_SERVICE_AUTH_REQUIRE_INBOUND=false` on it temporarily. Clock drift beyond
`CBP_SERVICE_AUTH_CLOCK_SKEW` (30s) also rejects tokens.

### 10.11 `500` where you expected `400`

A `DataIntegrityViolationException` from over-long input means a DTO is missing `@Size` bounds
mirroring its `@Column(length=…)`. Add the bound to the DTO — do not widen the column.

### 10.12 Generated gRPC classes not resolving in the IDE

```bash
mvn -B -pl ledger-grpc-api clean install
```

then re-import the Maven project. IntelliJ: *Maven → Reload All Projects*; VS Code: *Java: Clean
Java Language Server Workspace*. `.vscode/settings.json` sets
`java.configuration.updateBuildConfiguration: interactive`, so build changes need an explicit sync.

### 10.13 Slow or flaky builds

```bash
mvn -B -T 1C -DskipTests package      # parallel, no tests
mvn -B -o install                     # offline once dependencies are cached
docker pull postgres:16-alpine        # pre-pull the Testcontainers image
```

Do not parallelise Testcontainers integration tests until each module's container usage has been
checked for port and resource contention.

## 11. Conventions — how to add code safely

### 11.1 Non-negotiables

1. **Money is never a float.** Use `com.bank.common.money.Money` (BigDecimal + ISO-4217).
2. **The domain layer imports no framework.** No Spring, no JPA, no Jakarta in `domain/`.
3. **Every schema change is a new Flyway migration.** Forward-only, reviewed, never edited after
   it has been applied anywhere.
4. **No PII, PAN, or secrets in logs.** Card numbers are tokenized and never stored in the clear.
5. **Every request carries a correlation id.** Propagate `X-Correlation-Id` on every outbound call.
6. **Integrations go behind a port** with a stub adapter, selected by configuration — never by an
   `if` in business code.
7. **Fail closed.** A failed screening or risk call rejects the operation; it never falls through
   to "allow".
8. **Idempotency on anything that moves money.** Same key → same result, no double posting.

### 11.2 Adding an endpoint

1. `domain/` — the behaviour and invariants first, with a `*Test` that has no Spring context.
2. `application/` — the use-case; declare any new outbound need as a `port` interface.
3. `adapter/in/web/` — controller + request/response DTOs. Validate with `@NotBlank` **and**
   `@Size` bounds that mirror the column lengths.
4. `adapter/out/…` — implement the port; add a stub/no-op implementation for local and test use,
   selected by a config property.
5. `db/migration/V<n>__<change>.sql` if the schema moves.
6. `*IT` integration test extending the module's `AbstractIntegrationTest`.
7. If the endpoint is external, add its path predicate to `api-gateway/src/main/resources/application.yml`.

### 11.3 Adding a service

1. New module directory + `pom.xml` inheriting `banking-platform-parent`; add it to the parent
   `<modules>`.
2. Depend on `common-lib`; copy the `application.yml` shape (datasource, flyway schema, actuator,
   springdoc, logging pattern, `service-auth` block) from an existing service.
3. Claim a free port and a **new Flyway schema name**.
4. Add a `Dockerfile` modelled on an existing one — remember `ledger-grpc-api` if you use gRPC
   (section 10.1).
5. Add the service to `docker-compose.yml` and a route to `api-gateway`.
6. Add `AbstractIntegrationTest` using the **singleton container** pattern, and at least one `*IT`.
7. Write `docs/walkthroughs/<service>.md` using the template in `DEVELOPER_GUIDE_NEXT_PHASE.md`.

### 11.4 Recording a decision

Anything architectural gets an ADR in `docs/ADR/` using the template
(`Context → Decision → Alternatives considered → Consequences → References`). Copy
`docs/ADR/ADR-NNN-title.md` and take **the next unused number** (see section 12 — some numbers are
currently duplicated).

### 11.5 Definition of done

- [ ] `mvn -B verify` is green locally.
- [ ] Unit test for the domain rule; `*IT` for the wired path.
- [ ] Migration added if the schema changed; nothing already-applied was edited.
- [ ] No `double`/`float` money; no framework imports in `domain/`.
- [ ] No PII/PAN/secrets in logs; correlation id propagated on new outbound calls.
- [ ] New config documented in `.env.example` **with a safe (feature-off) default**.
- [ ] Gateway route added if the endpoint is external.
- [ ] OpenAPI renders at `/swagger-ui.html`.
- [ ] ADR written if a real decision was made; walkthrough updated if behaviour changed.
- [ ] `docs/PENDING_TASKS.md` ticked or amended.
